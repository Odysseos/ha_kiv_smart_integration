# Vakio KIV Local

Локальное управление **Vakio KIV Smart** со штатной прошивкой через MQTT
из Home Assistant. Независимый проект; не официальная интеграция Vakio.
Репозиторий: `ha_vakio_kiv_local`, домен компонента: `vakio_kiv_local`.

Проект доступен двумя способами:

| Способ | Для чего | Инструкция |
| --- | --- | --- |
| Интеграция HA, устанавливаемая через HACS | Добавлять приборы через интерфейс HA, без YAML и помощников для самого управления | [Установка интеграции](docs/integration.md) |
| Ручной вариант: blueprint и пакет YAML | Использовать автоматизации без установки custom component | [Ручная установка](manual/README.md) |

Файлы для ручной установки находятся в `manual/`. Для одного физического
прибора используйте только один способ управления.

## Возможности

- `cover` класса `damper`: закрытие и открытие на четверть, половину,
  три четверти и полностью.
- Список «Открытие заслонки»: **Нет / Малое / Среднее / Большое / Полное / Авто**.
- Переключение автоматического режима из HA и получение сообщений кнопок.
- Температура, влажность, отдельная память цели каждого прибора.
- Восстановление цели после запуска HA, регистрации прибора и, в интеграции,
  переподключения MQTT-клиента HA.

Нативная интеграция дополнительно поддерживает настройку задержки отчётов
через UI, выгрузку/перезагрузку без рестарта HA и диагностику.
Доступен экспериментальный [перенос карточки заслонки в «Климат»
её комнаты на автоматическом «Обзоре»](docs/integration.md#заслонка-в-климате-на-автоматическом-обзоре);
функция включена по умолчанию и отключается в параметрах прибора.

## Общий подход

Устройство управляет заслонкой, поэтому используются `cover` и
`device_class: damper`; автоматический режим представлен отдельным `select`.
Подробное обоснование: [выбор модели HA](docs/approach.md).

**MQTT в штатной прошивке 1.1.8 содержит ошибки и неполные состояния.**
Авторы прошивки не обеспечили подтверждение каждой команды, согласованность
JSON-переключения режима с реальным режимом и единый актуальный канал положения.
Проект компенсирует эти дефекты собственной памятью и порядком публикаций.
[Конкретные проблемы и обходы](docs/approach.md), [топики и порядок команд](docs/mqtt.md).

После команды UI показывает последнюю заданную цель. Это не гарантированное
измеренное положение и не подтверждение доступности прибора.

## Перед первым запуском

Требуются **HA 2025.10.0+**, настроенный MQTT в HA и подключённый к тому же
брокеру KIV Smart. Во всех примерах префикс прибора — `vakio_kiv`.
Нативный компонент использует MQTT-клиент HA; отдельные брокер и пароль
в настройках компонента не нужны. Для управления из HA облако производителя
и дополнительные интеграции не требуются.

**Первый запуск с пустой памятью задаёт ручное сезонное открытие:**

| Месяцы | Цель |
| --- | --- |
| Декабрь–февраль | Малое |
| Март, ноябрь | Среднее |
| Апрель, октябрь | Большое |
| Май–сентябрь | Полное |

Месяц берётся в часовом поясе HA. Это начальное значение; при смене месяца
автоматического изменения нет. Затем восстанавливается сохранённая цель.
Состояние ручного помощника в память интеграции автоматически не импортируется.

## Необязательно: Умный дом Яндекса

**YaHA не нужна для установки и работы Vakio KIV Local в Home Assistant.**
Если требуется управление через «Дом с Алисой», установите и настройте YaHA
отдельно по [инструкции подключения к Умному дому Яндекса](docs/yaha.md).
Там описаны генерация конфигурации, фильтр передачи и программы карточки.

## Совместимость и проверки

MQTT-протокол проверен с KIV Smart на штатной прошивке 1.1.8 ESP32.
Автоматизированные проверки компонента выполняются на HA 2025.10.4
с подменой MQTT-транспорта; проверки подключения к Яндексу — с YaHA 1.1.3.
Расширение «Обзора» зависит от внутренних генераторов интерфейса HA;
[поддерживаемые панели и ограничения](docs/integration.md#заслонка-в-климате-на-автоматическом-обзоре).
Совместимость с иными моделями, прошивками и всеми последующими версиями HA
не заявляется без проверки.
