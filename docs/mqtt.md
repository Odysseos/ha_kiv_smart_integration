# MQTT: протокол и восстановление состояния

[Общий подход](approach.md) · [интеграция](integration.md) · [ручная установка](../manual/README.md)

Командные топики и ограничения прошивки общие для двух реализаций.
Топики `vakio_ha/...`, Discovery и input_text ниже относятся только
к ручному blueprint. Нативная интеграция создаёт сущности напрямую,
использует Store HA и событие подключения MQTT-клиента.
В ней нет внутреннего JSON command topic: внешние команды можно подавать
в командные топики прибора или через действия HA. Числовые датчики
нативной интеграции сохраняют дробные значения и игнорируют неверные payload.

Ниже описано поведение, использованное для KIV Smart с прошивкой 1.1.8
(ESP32). Это результат проверки, а не спецификация или обещание производителя.
Общие причины выбора обходов перечислены в README.

## Два независимых префикса

Пример настройки: `topic_prefix: vakio_kiv`, `id_prefix: vakio_kiv_cover`.
Первый совпадает с настройкой физического прибора; второй задаёт постоянные
имена сущностей и внутренних MQTT-топиков HA. Они не обязаны совпадать.

| Топик примера | Назначение |
| --- | --- |
| `server/vakio_kiv/kivsmart/mode` | JSON-команды прибору |
| `vakio_kiv/workmode` | Текстовые команды `manual` / `super_auto` |
| `device/vakio_kiv/kivsmart/mode` | JSON-отчёты `capabilities` прибора |
| `device/vakio_kiv/kivsmart/system` | Регистрация прибора; обрабатывается `type: auth` |
| `vakio_kiv/temp` | Температура |
| `vakio_kiv/hud` | Влажность; `hud` — именно такое написание в протоколе |
| `vakio_ha/vakio_kiv_cover/json/command` | Внутренняя JSON-команда от HA cover/select |
| `vakio_ha/vakio_kiv_cover/json/cover/state` | Retained: `open` / `closed` |
| `vakio_ha/vakio_kiv_cover/json/cover/position` | Retained: `0`, `25`, `50`, `75`, `100` |
| `vakio_ha/vakio_kiv_cover/json/selection/state` | Retained: значение списка HA |
| `homeassistant/device/vakio_kiv_cover/config` | Retained: Device Discovery, четыре компонента |
| `homeassistant/status` | При `online` публикуются Discovery и сохранённая цель |

`temp` и `hud` напрямую читаются MQTT-сущностями. Текущие шаблоны приводят
значения к целому числу; дробная часть не сохраняется, некорректное значение
превращается в ноль. Проверки свойств YaHA отдельно подтверждают их привязку
к датчикам, но не меняют эту особенность входных MQTT-шаблонов.

## Ручное открытие

Чтобы задать половину открытия, blueprint публикует **в таком порядке**:

1. `vakio_kiv/workmode` → `manual`.
2. `server/vakio_kiv/kivsmart/mode` →
   `{"capabilities":{"on_off":"on","gate":2}}`.

Закрытие: тот же переход в `manual`, затем
`{"capabilities":{"on_off":"off"}}`. Последняя ненулевая ступень
сохраняется в памяти и не используется как признак открытого состояния.

## Автоматический режим

Публикации выполняются в другом порядке:

1. `server/vakio_kiv/kivsmart/mode` → `{"capabilities":{"on_off":"on"}}`.
2. `vakio_kiv/workmode` → `super_auto`.

JSON `capabilities.mode` прошивка 1.1.8 не применяет для переключения.
Поэтому реальное переключение выполняется через `/workmode`, а поле
`mode` не включается в собственную исходящую JSON-команду.

Все команды отправляются с `qos: 1`, **`retain: false`**. Retain используется
для Discovery и состояния HA, но не для командного канала.

## Откуда берётся состояние

В `input_text.vakio_kiv_cover_memory` хранится JSON вида:

```json
{"mode":"manual","power":"on","gate":2,"_ts":0}
```

`_ts` — служебное время принятого события, в работе заменяется временной
меткой. Память обновляют команды UI, допустимые внешние JSON-команды,
текстовый `/workmode` и JSON-отчёты прибора. `gate` может быть только `1…4`;
закрытие определяется по `power`. Неполный `capabilities` объединяется
с предыдущей записью: отсутствующие поля не обнуляются.

Неизвестные значения, `settings`, `relation` и некорректный JSON не меняют
состояние. Старые простые `/gate` и другие legacy state topics не слушаются.
Поэтому сторонний клиент, меняющий только legacy `/gate`, здесь не
гарантирует синхронизацию; используйте команды, перечисленные ниже.

После UI-команды интерфейс обновляется сразу. Отчёты прибора и сообщения
`/workmode` принимаются с задержкой `boot_report_window` (3 секунды).
Метка `_ts` не позволяет более раннему событию затереть новую команду или
регистрацию. Это временная защита, не полноценная нумерация сообщений
прошивки: если запоздавший отчёт пришёл уже после команды, без номера
версии состояния отличить его от свежего достоверно нельзя.

Свежий помощник со значением `unknown` считается пустой памятью и
инициализируется. Отсутствующая сущность или `unavailable` ожидается
до 30 секунд; при неуспехе выполнение прекращается. Некорректная память
также запускает сезонную инициализацию, описанную в README.

## Внешние MQTT-команды

Предпочтительный путь для полного поведения интеграции — внутренний топик:

```text
vakio_ha/vakio_kiv_cover/json/command
```

Примеры payload:

```json
{"capabilities":{"mode":"manual","on_off":"on","gate":3}}
```

```json
{"capabilities":{"mode":"super_auto","on_off":"on"}}
```

```json
{"capabilities":{"mode":"manual","on_off":"off"}}
```

Публикуйте **без retain**. Blueprint сохранит цель, выполнит реальные
команды в правильном порядке и обновит UI.

Также перехватываются JSON-команды в `server/vakio_kiv/kivsmart/mode`:
если в них есть допустимый `mode`, blueprint дополнит их переключением
через `/workmode`. Без `mode` он только учтёт команду в памяти и UI,
не переключая режим сам. Прямые текстовые `/workmode` меняют память и UI
без повторной публикации; такая команда сама по себе не включает питание.

Собственные исходящие JSON не содержат `mode`. Их получение через
подписку не запускает новый круг отправки. Прямые `/workmode` также
не переиздаются, что предотвращает бесконечную MQTT-петлю.

## Перезапуски и границы восстановления

При старте HA или сообщении `homeassistant/status: online` публикуется
Discovery и отправляется сохранённая цель. `system/auth` прибора также
запускает отправку цели. Стартовый отчёт, пришедший до `auth` и ещё
находящийся в окне задержки, отбрасывается по `_ts`.

Сохранение `input_text` выполняет HA. Резервная копия HA должна включать
состояние помощников; сама папка проекта не является копией текущей памяти.
При сбое до сохранения состояния, удалении помощника или очистке данных
HA последнее значение может быть потеряно.

Проект не получает подтверждение каждого движения и не проверяет
механическое достижение положения. Отображение цели, retained-сообщения
и состояние `open` не являются подтверждением подключения прибора.
