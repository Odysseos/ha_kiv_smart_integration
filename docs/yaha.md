# YaHA / Умный дом Яндекса — необязательная настройка

Этот раздел нужен только для управления через Яндекс. Для установки
и работы Vakio KIV Local в Home Assistant YaHA не требуется.

[Установка интеграции](integration.md) · [Главная](../README.md)

YaHA устанавливается и подключается к Яндексу отдельно. Обе реализации
проекта используют одно соответствие: cover → карточка `ventilation`,
select → программы, датчики → свойства этой же карточки.

## Нативная интеграция

### 1. Получите конфигурацию для своего прибора

Сначала добавьте прибор в Vakio KIV Local через «Настройки → Устройства
и службы». Все четыре сущности прибора — заслонка, список режимов,
температура и влажность — должны быть включены.

1. Откройте **«Инструменты разработчика» → «Действия»**.
2. Вверху справа нажмите **«Форма ввода»**, рядом с кнопкой «YAML».
   Если видите редактор со строками `action:` и `data: {}`, сейчас открыт
   режим YAML: сначала переключитесь на форму.
3. В списке действий найдите **«Получить конфигурацию YaHA»**.
   Под названием должен быть указан ID `vakio_kiv_local.get_yaha_config`.
4. В поле **«Прибор»** выберите добавленное устройство Vakio KIV Local.
   Вручную вводить `device_id` не нужно: форма подставит его сама.
5. Нажмите **«Выполнить действие»**.
6. Под формой появится ответ с разделами `yandex_smart_home` и
   `filter_hint`. Скопируйте ответ в текстовый редактор: дальше из него
   нужно перенести описание прибора и ID заслонки в настройку YaHA.

Таблица **«Все доступные параметры»** под редактором — справка.
Строка `device_id` в этой таблице не является полем ввода.
Прибор выбирается в форме из шага 4.

Если HA пишет **«Выбрано неизвестное действие»**, убедитесь, что
интеграция Vakio KIV Local установлена, а прибор добавлен. После установки
или обновления интеграции перезапустите HA и обновите страницу браузера.

Действие находит фактические ID сущностей через реестр HA, поэтому ответ
учитывает их переименования. Оно **не записывает файлы автоматически**
и не изменяет настройки YaHA. Получение ответа не требует установленной
YaHA; для передачи прибора в Яндекс она должна быть настроена отдельно.

### 2. Найдите файл настройки YaHA

Если настройки YaHA записаны непосредственно в `configuration.yaml`,
найдите в нём раздел `yandex_smart_home:`. Все изменения ниже вносятся
внутрь этого существующего раздела. Остальные его параметры сохраняйте.

Если вместо раздела указано подключение отдельного файла:

```yaml
yandex_smart_home: !include yandex_smart_home.yaml
```

редактируйте `yandex_smart_home.yaml`. В таком файле **не должно быть**
внешней строки `yandex_smart_home:`: он уже подключён под этим ключом.
Пример структуры отдельного файла приведён ниже.

### 3. Добавьте описание прибора в `entity_config`

В ответе действия раскройте `yandex_smart_home`, затем `entity_config`.
Внутри будет запись, ключ которой — ID заслонки, например
`cover.vakio_kiv_cover`. Скопируйте **эту запись целиком**, включая все её
вложенные параметры: `name`, `type`, шаблоны, действия, режимы и свойства.
Именно они объединяют заслонку, список режимов и датчики в одно устройство
Яндекса.

Если в вашей конфигурации уже есть `entity_config:`, вставьте запись
заслонки в него рядом с остальными устройствами. Второй ключ
`entity_config:` не добавляйте. Если раздела ещё нет, создайте его внутри
`yandex_smart_home:`.

`name` — название прибора в Яндексе. Его можно изменить, например на
«Приточный клапан». Необязательный `room` задаёт комнату в Яндексе,
например «Гостиная»; он располагается на одном уровне с `name` и `type`.

### 4. Разрешите передачу заслонки в Яндекс

`entity_config` описывает устройство, но сам по себе не включает его
передачу. Для этого нужно разрешить **основную сущность `cover`** в фильтре
YaHA. Отдельно добавлять `select` и датчики не нужно.

Если объекты для передачи выбираются в интерфейсе YaHA, разрешите там
сущность заслонки с ID из ответа действия. YAML-раздел `filter` в этом
случае добавлять не требуется; описание `entity_config` из шага 3 всё равно
нужно сохранить.

Если используете YAML-фильтр, в настройках YaHA выберите YAML как источник
фильтра. Добавьте ID заслонки в список `include_entities` внутри `filter`.
Существующие сущности и остальные правила фильтра сохраняйте. Например,
было:

```yaml
yandex_smart_home:
  filter:
    include_entities:
      - media_player.tv_livingroom
    include_entity_globs:
      - light.zigbee_*
```

Должно стать:

```yaml
yandex_smart_home:
  filter:
    include_entities:
      - media_player.tv_livingroom
      - cover.vakio_kiv_cover
    include_entity_globs:
      - light.zigbee_*
```

Если `include_entities` ещё нет, добавьте этот список в существующий
`filter`. Если нет и самого `filter`, создайте его внутри
`yandex_smart_home`, как в полном примере ниже.

В ответе действия также есть подсказка:

```yaml
filter_hint:
  include_entities:
    - cover.vakio_kiv_cover
```

Это **не готовый раздел конфигурации HA**. Из него нужен только ID
`cover.vakio_kiv_cover`, который добавляется в
`yandex_smart_home → filter → include_entities`. Сам ключ `filter_hint`
никуда не переносится.

### 5. Проверьте итоговую структуру

Ниже полный пример описания одного прибора и YAML-фильтра непосредственно
в `configuration.yaml`. ID здесь условные: используйте фактические ID
из ответа действия, в том числе внутри шаблонов и действий.
Если YaHA уже настроена, объедините этот пример с существующим разделом,
сохранив остальные устройства и параметры.

```yaml
yandex_smart_home:
  filter:
    include_entities:
    - cover.vakio_kiv_cover
  entity_config:
    cover.vakio_kiv_cover:
      name: Приточный клапан
      type: ventilation
      state_template: '{{ {''open'': ''on'', ''closed'': ''off''}.get(states(''cover.vakio_kiv_cover''), ''unavailable'') }}'
      turn_on:
        action: select.select_option
        target:
          entity_id: select.vakio_kiv_opening
        data:
          option: Полное
      turn_off:
        action: select.select_option
        target:
          entity_id: select.vakio_kiv_opening
        data:
          option: Нет
      modes:
        program:
          auto: Авто
          low: Малое
          medium: Среднее
          high: Большое
          max: Полное
      custom_modes:
        program:
          state_template: '{{ ''off'' if is_state(''cover.vakio_kiv_cover'', ''closed'') else states(''select.vakio_kiv_opening'') }}'
          set_mode:
            action: select.select_option
            target:
              entity_id: select.vakio_kiv_opening
            data:
              option: '{{ mode }}'
      custom_ranges:
        open: false
      properties:
      - type: temperature
        entity: sensor.vakio_kiv_temperature
      - type: humidity
        entity: sensor.vakio_kiv_humidity
      room: Гостиная
```

При подключении через `!include` начало файла `yandex_smart_home.yaml`
выглядит так:

```yaml
filter:
  include_entities:
    - cover.vakio_kiv_cover

entity_config:
  cover.vakio_kiv_cover:
    name: Приточный клапан
    room: Гостиная
    type: ventilation
    # Здесь также должны находиться ВСЕ остальные параметры записи
    # из ответа действия: шаблоны, действия, режимы и свойства.
```

Последний фрагмент показывает только отступы и структуру отдельного файла.
Для рабочего описания прибора перенесите всю запись из ответа действия,
а не только `name`, `room` и `type`.

### 6. Примените настройки

Проверьте конфигурацию HA и перезапустите HA. Затем обновите устройства
провайдера в приложении «Дом с Алисой».

Для каждого следующего прибора повторите действие
`vakio_kiv_local.get_yaha_config`: добавьте его запись в тот же
`entity_config` и разрешите его основной `cover` выбранным способом
фильтрации. Если впоследствии переименовали сущности в HA, заново
сформируйте ответ и замените описание этого прибора, включая старый ключ
`cover` и ID в фильтре.

## Ручной вариант

Готовая запись находится в
[manual/includes/vakio_cover.yaml](../manual/includes/vakio_cover.yaml).
Для нейтрального примера с `cover.vakio_kiv_cover` фильтр может быть таким:

```yaml
yandex_smart_home:
  filter:
    include_entity_globs:
      - cover.vakio_*
```

Добавляйте glob в существующий список, а не заменяйте фильтр. Явное разрешение
конкретного cover работает для обоих способов и не зависит от его имени.

## Управление

| Команда / программа УДЯ | Результат |
| --- | --- |
| Включить | Полное, manual |
| Выключить | Нет, manual |
| low | Малое |
| medium | Среднее |
| high | Большое |
| max | Полное |
| auto | Авто, super_auto |

Программы берут состояние из select. При закрытом cover передаётся выключенное
устройство без фиктивной программы открытия. Неизвестный или недоступный cover
даёт unavailable. Числовая функция open отключена в УДЯ; в HA ползунок остаётся.
Яндекс использует собственные подписи программ. Произвольные слова из списка
HA не становятся пользовательскими названиями режимов Яндекса.

Не нужно отдельно экспортировать select или датчики: свойства уже входят
в основную карточку. Их отдельный экспорт создаёт дополнительные устройства.

## Устройство не появилось

`entity_config` **не разрешает передачу автоматически**. Проверьте:

1. Фактический ID основного cover включён выбранным способом фильтрации.
2. `cover.blind_*` не соответствует `cover.vakio_*`.
3. Cover существует и имеет состояние open или closed.
4. Ссылки в entity_config совпадают с реестром HA.
5. Обновлён список устройств провайдера в «Дом с Алисой».

Если меняли тип уже переданного устройства, удалите прежнюю карточку УДЯ
и повторно обновите список.

[параметры устройства](https://docs.yaha-cloud.ru/master/config/entity/),
[пользовательские режимы](https://docs.yaha-cloud.ru/master/advanced/capabilities/mode/).
