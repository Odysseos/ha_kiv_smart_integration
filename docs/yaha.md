# YaHA / Умный дом Яндекса — необязательная настройка

Этот раздел нужен только для управления через Яндекс. Для установки
и работы Vakio KIV Local в Home Assistant YaHA не требуется.

[Установка интеграции](integration.md) · [Главная](../README.md)

YaHA устанавливается и подключается к Яндексу отдельно. Обе реализации
проекта используют одно соответствие: cover → карточка `ventilation`,
select → программы, датчики → свойства этой же карточки.

## Нативная интеграция: один файл для всех клапанов

Действие **`vakio_kiv_local.export_yaha_config`** само собирает описание всех
добавленных клапанов и записывает его в файл:

```text
includes/yandex_smart_home_vakio.yaml
```

Путь отсчитывается от каталога конфигурации HA. Выбирать отдельное устройство
или копировать большое описание для каждого клапана не требуется.
YaHA устанавливается отдельно; для создания файла она не нужна.

### 1. Сформируйте файл

Сначала добавьте все приборы в Vakio KIV Local. У каждого должны быть включены
все четыре сущности: заслонка, список режимов, температура и влажность.
Назначьте устройствам понятные имена и комнаты в HA.

1. Откройте **«Инструменты разработчика» → «Действия»**.
2. Нажмите **«Форма ввода»** справа вверху, рядом с кнопкой «YAML».
3. Выберите **«Сохранить конфигурацию всех клапанов для YaHA»**
   (`vakio_kiv_local.export_yaha_config`).
4. У действия нет параметров: поле выбора прибора не требуется.
5. Нажмите **«Выполнить действие»**. Действие доступно администратору HA.

В режиме YAML вызов выглядит так:

```yaml
action: vakio_kiv_local.export_yaha_config
data: {}
```

Каталог создаётся автоматически. Ответ содержит путь `file`, число
клапанов `device_count` и список их основных cover в `filter_hint`.
Действие действительно записывает файл; в отличие от
`get_yaha_config`, переносить ответ в конфигурацию вручную не нужно.

Генератор использует фактические ID через реестр HA, поэтому учитывает
переименования сущностей. Имя берётся из устройства HA, комната — из
назначения сущности заслонки или, если оно отсутствует, устройства.
Если комната не назначена, поле `room` не добавляется.

### 2. Два самостоятельных файла настройки YaHA

Используются два файла одинаковой структуры. Каждый содержит свой `filter`
и `entity_config`, без внешнего ключа `yandex_smart_home:`:

| Файл | Содержимое | Кто обновляет |
| --- | --- | --- |
| `includes/yandex_smart_home.yaml` | Все остальные устройства, их фильтр и общие параметры YaHA | Вы |
| `includes/yandex_smart_home_vakio.yaml` | Только текущие клапаны Vakio KIV Local, их фильтр и описание | Действие генерации |

В `includes/yandex_smart_home.yaml` сохраните существующие параметры и
описания остальных устройств. Например:

```yaml
filter:
  include_entities:
    - media_player.tv_livingroom
  include_entity_globs:
    - light.zigbee_*

entity_config:
  media_player.tv_livingroom:
    name: Телевизор
    room: Гостиная
```

Переносить эти устройства в другие файлы не нужно. Из этого файла удалите
только прежние описания клапанов и отдельные правила, добавленные специально
для их передачи. Правила для остальных устройств сохраните.

Второй файл создаётся действием `vakio_kiv_local.export_yaha_config`
автоматически. Его `filter.include_entities` содержит точные ID основных
cover всех клапанов, а `entity_config` — их полные описания.
Переименования учитываются одновременно в обоих разделах.
Никаких glob вроде `cover.vakio_*` для клапанов больше не требуется:
генератор не включает старые MQTT-сущности и дополнительные select/датчики.

### 3. Подключите оба файла через пакеты HA

В `configuration.yaml` используйте:

```yaml
homeassistant:
  packages:
    yaha_other:
      yandex_smart_home: !include includes/yandex_smart_home.yaml
    yaha_vakio:
      yandex_smart_home: !include includes/yandex_smart_home_vakio.yaml
```

Прежнюю отдельную строку
`yandex_smart_home: !include includes/yandex_smart_home.yaml`
на верхнем уровне `configuration.yaml` удалите: этот же файл теперь
подключается внутри пакета `yaha_other`. Оставлять оба подключения нельзя.

Если уже есть `homeassistant:`, добавьте `packages:` внутрь него.
Если уже есть и `packages:`, добавьте только записи `yaha_other:` и
`yaha_vakio:` рядом с существующими пакетами. Повторяющиеся ключи
создавать нельзя. Если `packages` уже подключён через `!include`,
добавляйте записи в подключаемый файл; пути `!include` отсчитываются
от расположения того файла, в котором они написаны.

Сначала выполните генерацию из шага 1, чтобы файл клапанов существовал.
Итоговое расположение:

```text
configuration.yaml
includes/
  yandex_smart_home.yaml
  yandex_smart_home_vakio.yaml
```

Пакеты — штатный механизм объединения настроек HA. Оба файла дополняют
**одну интеграцию YaHA**, а не создают два подключения к Яндексу.
Списки разрешённых сущностей и правила фильтра объединяются вместе
с описаниями устройств. Поэтому файлы самостоятельны по структуре,
но фильтр после загрузки общий: исключение в одном файле может влиять
на устройство, описанное в другом. Проверьте, нет ли в файле остальных
устройств широкого исключения, которое запрещает cover клапанов.
Общие параметры подключения YaHA задавайте только в первом файле.

### 4. Используйте YAML-фильтр

В настройках YaHA выберите **YAML** как источник фильтра.
Файл клапанов уже содержит разрешение передачи каждого основного cover:
копировать `filter_hint` в файл остальных устройств не требуется.
`filter_hint` остаётся в ответе действия как справочная информация.

Если объекты выбираются в UI YaHA вместо YAML-фильтра, разрешения из обоих
файлов не управляют этим выбором: основные cover нужно разрешить в UI.
Для использования автоматически создаваемого фильтра выбирайте YAML.

Генератор записывает только `includes/yandex_smart_home_vakio.yaml`.
Файл остальных устройств и `configuration.yaml` он не меняет.
Если по указанному пути находится файл без метки генератора, действие
откажется его перезаписывать. Если у любого клапана отсутствует или
отключена нужная сущность, предыдущий файл сохраняется целиком.

### 5. Применяйте изменения

После первоначального подключения пакета проверьте конфигурацию HA,
перезапустите HA и обновите устройства провайдера в «Доме с Алисой».

После добавления или удаления клапана, изменения имени, комнаты либо ID
сущностей снова выполните `vakio_kiv_local.export_yaha_config`, затем
проверьте конфигурацию и перезапустите HA, обновите устройства в Яндексе.
Генерация сама по себе не перезагружает YaHA и ничего не отправляет в Яндекс.
Фильтр клапанов обновляется тем же действием вместе с их описаниями.

Файл генерируется целиком заново, а не дополняется. При отсутствии клапанов
он содержит пустые `filter.include_entities` и `entity_config`, удаляя
прежние записи клапанов из этого файла. Фильтр остальных устройств остаётся
неизменным; учитывайте, что YaHA без каких-либо правил включения/исключения
по умолчанию не ограничивает передачу устройств.
Не редактируйте его вручную: повторная генерация заменит ручные правки.
Имена и комнаты задавайте в HA. Действие выполняется по запросу; при запуске
HA файлы автоматически не перезаписываются.

### Дополнительно: получить описание одного прибора без записи файла

Действие **`vakio_kiv_local.get_yaha_config`** по-прежнему доступно для
просмотра или ручного переноса описания одного прибора:

1. В «Инструменты разработчика → Действия» нажмите **«Форма ввода»**.
2. Выберите **«Получить конфигурацию YaHA»**
   (`vakio_kiv_local.get_yaha_config`).
3. В поле **«Прибор»** выберите устройство и нажмите **«Выполнить действие»**.
4. В ответе возьмите запись cover из `yandex_smart_home.entity_config`.

Это действие файлы не записывает. Таблица «Все доступные параметры»
в режиме YAML является справкой, а не полем выбора устройства.

## Ручной вариант

Готовая запись находится в
[manual/includes/vakio_cover.yaml](../manual/includes/vakio_cover.yaml).
Для нейтрального примера с `cover.vakio_kiv_cover` фильтр может быть таким:

```yaml
yandex_smart_home:
  filter:
    include_entity_globs:
      - cover.vakio_*
```

Добавляйте glob в существующий список, а не заменяйте фильтр. Явное разрешение
конкретного cover работает для обоих способов и не зависит от его имени.

## Управление

| Команда / программа УДЯ | Результат |
| --- | --- |
| Включить | Полное, manual |
| Выключить | Нет, manual |
| low | Малое |
| medium | Среднее |
| high | Большое |
| max | Полное |
| auto | Авто, super_auto |

Программы берут состояние из select. При закрытом cover передаётся выключенное
устройство без фиктивной программы открытия. Неизвестный или недоступный cover
даёт unavailable. Числовая функция open отключена в УДЯ; в HA ползунок остаётся.
Яндекс использует собственные подписи программ. Произвольные слова из списка
HA не становятся пользовательскими названиями режимов Яндекса.

Не нужно отдельно экспортировать select или датчики: свойства уже входят
в основную карточку. Их отдельный экспорт создаёт дополнительные устройства.

## Устройство не появилось

`entity_config` **не разрешает передачу автоматически**. Проверьте:

1. Фактический ID основного cover включён выбранным способом фильтрации.
2. `cover.blind_*` не соответствует `cover.vakio_*`.
3. Cover существует и имеет состояние open или closed.
4. Ссылки в entity_config совпадают с реестром HA.
5. Обновлён список устройств провайдера в «Дом с Алисой».

Если меняли тип уже переданного устройства, удалите прежнюю карточку УДЯ
и повторно обновите список.

[параметры устройства](https://docs.yaha-cloud.ru/master/config/entity/),
[пользовательские режимы](https://docs.yaha-cloud.ru/master/advanced/capabilities/mode/).
